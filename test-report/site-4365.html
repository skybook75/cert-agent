5. 운영 시나리오 인수 테스트 (인증서 관리자 관점)

실제 PC 서버판을 띄우고 화면을 직접 조작하는 방식으로, 인증서 관리자가 처음 설치해 대장을 옮기고 수집·승인·알림·갱신·배포·원복까지 하는 하루 업무를 12개 시나리오로 수행했습니다. 데이터는 서버 4대(nginx·Apache·Tomcat·IIS)를 흉내 낸 폴더의 인증서 13개(체인 PEM·DER·PKCS#12·공동인증서·손상 파일·개인키 파일·2025년 사본)와, 담당자가 손으로 관리해 온 엑셀 관리대장 10행(점 날짜·담당자 누락·날짜 오타·이메일 오타·중복·폐기 서버 포함)입니다. 결과: 검증 항목 51/51 통과, 테스트 중 발견 8건(수정 6·설명 보완 1·정상 동작이라 운영 안내만 1). 단계별 화면 증적은 결과 페이지(https://skybook75.github.io/cert-agent/test-report/)에 있습니다.

배포 범위 (현재와 다음 단계)

현재: 배포가 승인되면 플랫폼이 인증서 파일을 단계별 배포 폴더(deploy/개발·테스트·교육·운영/인증서명/)에 놓고 지문·만료일을 기록하며, 이전 파일은 history에 보관해 원복할 때 되돌립니다. 웹서버(nginx·IIS 등)에 설치하고 재시작하는 일은 각 서버 담당자가 하며, Agent가 서버 설정을 직접 바꾸지는 않습니다.

다음 단계(AWS EC2 테스트): Linux·Windows 서버를 만들어 실제 웹서버에 인증서를 두고, 서버별 수집 Agent가 플랫폼으로 결과를 올리며, 배포 Agent가 승인된 인증서를 설치 → 설정 검사(nginx -t 등) → 재적용 → 실패 시 자동 원복까지 하도록 확장해 검증합니다.
