# 인증서 관리 플랫폼 (E2E 서비스)

수집 Agent · 알림 Agent · QA 챗봇(RAG + Claude)과 관리대장 등록·대조 · 승인 · 4단계 배포/원복 · 보고서를 하나로 묶은 PC 실행형 서비스.

## 실행 (PC)
1. Python 3.11 이상 설치
2. `실행.bat` 더블클릭 → http://localhost:8000
3. 처음 실행하면 **최초 관리자 계정**을 만들고, 관리 탭에서 사용자(담당자·검토자·승인자·조회자)와 SMTP를 설정
4. 매일 알림·메일: `작업스케줄러_등록.bat` 실행(매일 08:50에 `알림_배치.bat` → `agents.py notify --send`)

환경변수(선택): `ANTHROPIC_API_KEY`(Claude 챗봇), `CLAUDE_MODEL`(기본 claude-sonnet-5-5), `SMTP_PASSWORD`(SMTP 계정 사용 시)

## 보안
플랫폼 계정(PBKDF2-SHA256 해시), 세션 쿠키(HttpOnly·SameSite=Strict)+CSRF 토큰, 5회 실패 10분 잠금, 첫 로그인 비밀번호 변경,
쓰기는 작업 단위로만(허용 컬렉션·필드·문서 ID·상태 전이 검사, 처리자는 세션 기준 기록), 담당자 조회·처리 범위 제한,
배포 요청자·검토자·승인자 분리, 개인키·SMTP 비밀번호·Claude 키 미저장, 127.0.0.1 전용, CSP·X-Frame-Options 헤더.

## PFX 비밀번호 보관함
- 담당자·관리자가 'PFX 비밀번호' 탭에서 비밀번호와 적용 범위(파일 1개 / 폴더(하위 포함) / 전체 PFX — 전체는 관리자만)를 입력하면 서버가 **AES-256-GCM**으로 암호화해 DB에 암호문만 저장합니다. 문서 ID를 추가 인증 데이터(AAD)로 묶어 암호문을 다른 항목으로 옮기면 복호화되지 않습니다.
- 암호화 키는 DB와 다른 곳(%APPDATA%\\cert_platform\\vault.key, 윈도우에서는 현재 사용자만 접근하도록 권한 제한)에 둡니다. DB 파일만 유출되어서는 비밀번호를 풀 수 없습니다. 키를 잃어버리면 비밀번호를 다시 등록해야 하므로 키 파일은 DB와 **따로** 백업합니다.
- 저장된 비밀번호는 관리자를 포함해 누구도 다시 볼 수 없고(API도 메타정보만 반환), 교체·삭제만 할 수 있습니다. 등록·교체·삭제는 감사 로그에 남고 값은 기록하지 않습니다.
- 수집 Agent는 PFX를 열 때 비밀번호 없이 먼저 시도하고, 안 열리면 범위가 맞는 비밀번호(파일 → 깊은 폴더 → 전체, 최근 성공 순)만 메모리에서 복호화해 차례로 씁니다. 결과는 '비밀번호 필요' / '비밀번호 불일치(보관함 N개 시도)'로 구분되고, 'PFX 비밀번호' 탭의 '비밀번호가 필요한 파일'에서 바로 등록할 수 있습니다.
- 웹 시연판(서버 없음)은 브라우저에서 RSA-OAEP-3072 공개키로 암호화해 저장하고, 복호화용 개인키는 관리자의 '보관함 비밀번호'(PBKDF2 60만 회 + AES-GCM)로 감싸 둡니다. 수집할 때만 보관함을 열고 10분 뒤 자동으로 잠급니다.

## QA 챗봇 — 가이드 업로드 RAG · 답변 검증 AI
- **가이드 업로드(관리자)**: QA 챗봇 탭의 '가이드 업로드'에 PDF/.docx/.html/.txt/.md/.json 파일을 올리면 제목 단위로 문단을 나누고(300~900자) 발급기관을 자동 감지해 U01, U02… 번호로 저장한 뒤 검색 색인(BM25, 한글 2-gram)을 즉시 다시 만듭니다. 삭제하면 바로 색인에서 빠집니다. PDF는 pdf.js로 글자를 뽑아(글자 크기로 제목 줄 판별, 반복 머리글·쪽번호 제거, 한글 CID 글꼴 지원) 같은 방식으로 나눕니다. 글자가 없는 스캔본 PDF는 사유와 함께 거절합니다. '기본 가이드 12종'·'업로드 N종'을 누르면 목록과 문단을 볼 수 있습니다.
- **답변**: 질문과 가장 가까운 문단을 내장 가이드(G01~)와 업로드 가이드(U01~)에서 함께 찾아 Claude에 근거로 넘기고, 답변에는 [U01-1] 같은 근거 번호가 붙습니다. 키가 없으면 근거 문단을 그대로 보여 줍니다.
- **답변 검증 AI**: 답변이 나오면 별도의 AI 호출이 같은 근거와 답변만 보고 정확도·품질(0~100)을 매기고 적합/주의/부적합, 근거 없는 내용, 빠진 내용, 한두 문장 코멘트를 답변 바로 아래에 붙입니다. 규칙 검사(잘못된 인용 번호, 근거에 없는 수치·명령 옵션)도 함께 표시하며, 잘못된 인용이 있으면 정확도는 59점을 넘지 못합니다. 검증 AI를 쓸 수 없으면 규칙 검사 결과만 표시합니다.
- 검증: `node tests/e2e_qa_rag.cjs`(12/12), 실제 LLM 판정 결과 `results/verifier_llm_eval.json`(정답 3건 적합, 오답·모호 답변 3건 부적합).
